这篇没有代码，纯记录生活，技术同学可以直接跳过，开玩笑的，看完也许有点别的收获。

入门装备

入坑手冲咖啡，装备按最简原则配齐：一个手摇磨豆机、一个 V60 滤杯配滤纸、一个细口壶、一个电子秤带计时，全套下来不算贵，比天天买咖啡厅的账单划算。第一杯自己冲的咖啡谈不上惊艳，甚至有点寡淡，但那种亲手做出来的成就感是真实存在的。

参数上踩过的坑：水温太高萃取过度又苦又涩，九十二度左右是多数浅烘豆的舒适区；粉水比从一比十五起步调；研磨度对手冲的影响立竿见影，太细苦、太粗淡，磨豆机的刻度试出来一档偏粗半档偏细的位置，就锁定它。

风味与记录

喝了一阵之后开始能分辨风味了，酸、甜、苦之外，居然真的能喝出描述里的花果香，这件事的玄学外壳裂开了一条缝。我的做法是每支豆子记录冲煮参数和感受，几页笔记下来，偏好逐渐清晰：喜酸就挑非洲豆，喜醇厚就看曼特宁方向。

手冲这件事最大的吸引力在于它是个可调参的小系统，水温柔比研磨度水流高度，每个变量都能实验，对工程师来说简直量身定做。周末早上给自己冲一杯，闻着香气等水温降下来的十分钟，是一天里少有的完全属于自己的时间。

过程中的小心得

剩菜以前是等凉透再进冰箱，被科普之后才知道要尽快冷藏，细菌繁殖的窗口期比想象中短。生活里很多想当然的习惯，较真起来都有另一套答案。

随手记两个小教训：阳台那盆绿萝浇得太勤，根都泡烂了，剪掉烂的部分重新扦插，现在改了策略，土干了再浇，反倒精神了不少。

煮饭水放多了，成品介于饭和粥之间。后来老老实实用量杯，或者直接看水位线，凭感觉这种事，在厨房里基本靠不住。

package cn.lvxi.dm.auth.app.log;

import cn.lvxi.common.infra.operationlog.OperationLogInfo;
import cn.lvxi.common.infra.operationlog.OperationLogRecorder;
import cn.lvxi.dm.common.remote.api.LogApiService;
import cn.lvxi.dm.common.remote.model.OperationLogRO;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.apache.dubbo.config.annotation.DubboReference;
import org.springframework.stereotype.Component;

import java.util.List;

/**
 * 认证服务的操作日志记录器：批量经 RPC 上报公共服务写入 operation_log
 */
@Slf4j
@RequiredArgsConstructor
@Component
public class RpcOperationLogRecorder implements OperationLogRecorder {

    @DubboReference
    private final LogApiService logApiService;

    @Override
    public void record(List<OperationLogInfo> infos) {
        if (infos == null || infos.isEmpty()) {
            return;
        }
        try {
            List<OperationLogRO> roList = infos.stream()
                    .map(this::toRo)
                    .toList();
            logApiService.createOperationLogs(roList);
        } catch (Exception e) {
            log.warn("操作日志批量上报失败, size={}", infos.size(), e);
        }
    }

    private OperationLogRO toRo(OperationLogInfo info) {
        OperationLogRO ro = new OperationLogRO();
        ro.setUserId(info.getUserId());
        ro.setUsername(info.getUsername());
        ro.setTitle(info.getTitle());
        ro.setOperationType(info.getOperationType());
        ro.setRequestMethod(info.getRequestMethod());
        ro.setRequestUrl(info.getRequestUrl());
        ro.setRequestParams(info.getRequestParams());
        ro.setResponseData(info.getResponseData());
        ro.setIp(info.getIp());
        ro.setStatus(info.getStatus());
        ro.setErrorMsg(info.getErrorMsg());
        ro.setExecutionTime(info.getExecutionTime());
        return ro;
    }
}

延伸几句

关于咖啡因的摄入，值得认真对待的只有两件事：总量和时段。了解自己的耐受度，下午三点以后基本戒断，剩下的就交给喜好。至于健康的长长短短的传闻，适量这个原则都成立。

咖啡喝了几年的一个总结：器材的投入应该跟着需求的明确程度走。还没搞清楚自己喜欢什么的时候，入门装备加试错的心思比旗舰设备更划算，等口味稳定了再升级，钱才花在点子上。

咖啡的仪式感这个词被用滥了，但那个动作本身确实有价值：磨豆的十几秒、注水的两分钟，是一段强制离屏的时间。每天里有这么几分钟完全属于自己，这件事的价值可能大于咖啡因本身。

又想到一些

最后聊点感受：做技术这些年，越来越觉得最好的状态是既投入又抽离。投入是把事情做好，抽离是时不时跳出来看看方向对不对，两者缺一，要么辛苦没产出，要么轻松跑偏路。

写着写着想到，很多技术选择本质上都是在回答同一个问题：这个方案在出问题的时候是什么样子。不出问题的方案人人都写得出来，区分度全在故障时刻的表现。多想一层失败路径，很多纠结就自动有了答案。

这类经验在文档里通常只有一行字，背后的排查却是一整个下午。技术工作的大部分时间都花在这些不会写进简历的细节里，所以这些细节才更需要有人写出来，哪怕只是给未来某一天忘了的自己。

顺带聊聊方法论：遇到不熟悉的领域，我的习惯是先把最小闭环跑通，哪怕每一步都很粗糙。跑通之后再逐段替换成正经实现，过程中每一步都有可运行的版本。这个思路在工作和生活里都屡试不爽，比憋大招的成功率高得多。

def order_flow(user, cart):
    """下单主流程"""
    if not user.is_authenticated:
        raise AuthError("未登录")

    if not user.has_permission("order:create"):
        raise PermissionError("无权限")

    with transaction() as tx:
        stock = inventory.check(cart.items)
        if not stock.ok:
            return Result.fail("库存不足")

        order = Order.create(user, cart)
        inventory.lock(cart.items)
        tx.commit()

    mq.send("order.timeout", order.id, delay=1800)
    return Result.ok(order.id)
